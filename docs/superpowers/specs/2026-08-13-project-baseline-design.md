# 项目资料、文档与演示开发基线设计

## 目标

在不进行全面重构的前提下，把用户沟通、UI 原稿和方案 PPT 沉淀为轻量项目文档，并修复影响后续演示开发的最明显基础问题。

## 方案

- 使用 `AGENTS.md` 保存最高优先级规则和长期上下文。
- 使用 `docs/` 分别保存项目介绍、总需求、演示规则、页面链路、UI 索引和变更记录。
- 原始 PPT 与 UI 图保存在本地 `projectFiles/`，不进入 Git 历史，不上传远程。
- Dashi 使用独立项目，并按阶段或业务链路拆分任务。
- 代码只做最小整理：增加静态资源检查并修复缺失 Logo；不重构全部页面。

## 当前范围

- 资料归档和逐页检查。
- 文档体系建立。
- Logo 静态资源问题修复。
- 构建和工作树验证。

## 不在当前范围

- B2B/B2C 页面正式开发。
- 全产业链新页面开发。
- 真实接口、支付、金融、IoT 和生产安全体系。
- 全仓库格式化、TypeScript 改造或测试框架建设。

## 验收

- 文档能够说明项目定位、需求、页面和开发规则。
- 本地-only规则清晰可见。
- UI/PPT 资料目录和页面对应关系清楚。
- 静态资源检查能够发现缺失文件。
- 生产构建成功，且不再报告 Logo 资源缺失。
