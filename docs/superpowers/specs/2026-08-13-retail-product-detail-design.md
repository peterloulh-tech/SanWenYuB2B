# 个人消费零售商品详情页设计

确认日期：2026-08-13

## 目标

为个人消费频道补齐 `/retail/products/:id` 商品详情页，使零售首页现有 7 件商品都能进入对应详情。页面用于 PC 前端静态演示，重点清楚表达小包装零售商品的价格、规格、来源、配送承诺和购买入口，不接入真实交易能力。

## 已确认范围

- 7 件商品共用一个数据驱动的详情页模板，不分别制作 7 个页面组件。
- 页面沿用现有个人消费频道页头、身份切换、蓝白主视觉和少量暖橙购买强调色。
- 详情页首屏必须看到商品名称、零售价、规格、配送信息、数量和购买按钮。
- 商品、价格、来源、配送时效和售后说明都明确标为演示数据或演示说明。
- 本轮只打通“零售首页 → 商品详情 → 返回零售首页”的页面链路。
- “加入购物车”和“立即购买”保留为可点击演示入口，但本轮只显示阶段提示，不进入尚未确认的购物车或结算页面。

## 方案比较

### 方案 A：统一数据驱动模板（采用）

用一个 `RetailProductPage` 读取路由中的商品 ID，再从 `retailData` 获取对应详情字段。7 件商品共用页面结构，只变化内容。

优点是页面一致、修改范围集中、便于后续接入购物车；代价是需要补齐每件商品的详情字段。

### 方案 B：每件商品独立页面

每件商品可以自由排版，但会产生重复组件和样式，后续维护成本高，不符合快速静态演示目标。

### 方案 C：首页弹窗承载详情

改动最少，但不能形成独立路由，也无法自然接续购物车和结算链路，不采用。

## 页面结构

### 1. 公共页头

- 复用现有 `SiteHeader`，保持“当前：个人消费”身份入口、零售频道导航和购物车占位入口。
- 不改变企业频道页头和企业页面导航。

### 2. 面包屑与返回入口

- 主内容顶部显示“个人消费首页 › 商品分类 › 商品名称”。
- “个人消费首页”可点击返回 `/retail`。
- 分类名称来自 `retailCategories`；不新增独立分类列表页。

### 3. 商品主信息区

主信息区在 PC 上采用左右两栏：

- 左侧展示现有商品大图和商品标签，不增加缩略图相册或图片切换。
- 右侧依次展示商品名称、简短卖点、“演示数据”标识、零售价、包装规格、来源地或来源说明、配送方式、预计送达和冷链保障。
- 零售价统一使用“零售价 ¥xx.xx / 单位”，不得出现企业端参考价、起订量或询价表达。
- 数量区显示减号、数量和加号，演示范围限定为 1～9；数量只保存在当前页面内，不写入持久化购物车。
- 主操作为“立即购买”，次操作为“加入购物车”。两个按钮均可点击，但只打开阶段提示层。
- 阶段提示说明“购物车与结算页面将在后续文字草图确认后开放”，并提供“继续浏览”关闭按钮。

### 4. 详情说明区

主信息区下方用三个清晰分区展示：

- 商品介绍：主要食材、商品特点和适用场景。
- 食用与保存：食用建议、冷藏或冷冻方式及演示保质说明。
- 配送与售后：冷链配送范围、签收检查和演示售后说明。

内容保持短段落或项目式信息，避免长篇营销文字；不加入评价、销量榜或推荐瀑布流。

## 数据与组件边界

- `src/data/retailData.js` 继续作为零售商品的唯一数据来源，并为每件商品补充 `shortDescription`、`origin`、`delivery`、`arrival`、`coldChain`、`description`、`servingAdvice`、`storageAdvice` 和 `afterSales` 等详情字段。
- `RetailProductPage` 负责按路由参数查找商品、渲染详情、维护当前数量和控制阶段提示层。
- 商品查找逻辑提取为可单独测试的纯函数，例如 `getRetailProductById(id)`；页面不复制商品数组。
- 现有 `RetailHomePage` 的“查看详情”改为导航至商品的 `detailPath`。
- 现有首页“立即购买”行为保持不变，仍提示游客登录或注册；本轮不借机改造首页购买流程。
- 详情页样式继续写入 `src/styles/retail-pages.css`，使用 `retail-product-detail-` 等明确前缀，避免影响企业页面。

## 路由与状态

- 新增路由 `/retail/products/:id`，由 `RetailProductPage` 处理。
- 合法商品 ID 显示对应详情，直接刷新该地址也应正常展示。
- 找不到商品 ID 时显示零售频道内的轻量错误状态：“未找到该商品或商品已下架（演示）”，并提供“返回个人消费首页”按钮；不静默跳转到企业首页。
- 数量变化和提示层状态仅存在于当前页面内；刷新后恢复数量 1。
- 不发送网络请求，不写入本地存储，不产生真实订单或库存变化。

## 视觉与易用性

- 1920×1080 下主信息和详情说明尽量在一屏内完整呈现。
- 1366×768 下允许少量纵向滚动，但不得出现整页横向滚动；首屏仍需露出价格、配送信息和两个购买按钮。
- 商品名称、价格和按钮使用较大字号；按钮文字完整，点击区域适合中老年用户。
- 商品图片使用现有本地资源，不在本轮生成新图片。
- 所有演示属性采用可见文字标识，不能只依赖颜色或悬浮提示。

## 测试与验证

- 数据测试：7 个商品 ID 均可查询到唯一商品；未知 ID 返回空结果。
- 路由与页面测试：首页 7 个“查看详情”都指向对应 `detailPath`；合法 ID 展示正确名称、价格和规格；未知 ID 展示错误状态。
- 交互测试：数量不能小于 1 或大于 9；两个购买入口都能打开阶段提示并可关闭。
- 回归检查：首页游客“立即购买”仍跳转登录或注册提示，企业页面不受影响。
- 执行项目相关自动测试、静态资源检查和生产构建。
- 使用浏览器检查 1366×768 和 1920×1080，无页面级横向滚动，关键内容与操作可见。

## 验收标准

- 零售首页 7 件商品均能进入内容匹配的商品详情页。
- 详情页明确展示商品图、名称、演示标识、零售价、规格、来源、配送承诺、数量和购买入口。
- “加入购物车”和“立即购买”不会进入未确认页面或制造真实交易结果。
- 未知商品地址有清晰错误状态和返回入口。
- 个人消费与企业交易的价格和操作表达没有混用。
- 自动测试、静态资源检查和生产构建通过；两种目标 PC 分辨率无整页横向滚动。

## 本轮不做

- 购物车页面、结算页面、下单成功页及其路由跳转。
- 真实库存、SKU 或规格切换、优惠券、支付、收藏、评价、销量和推荐算法。
- 购物车持久化、真实登录态、订单接口、库存扣减和售后提交。
- 新图片生成、企业页面调整或全项目重构。
