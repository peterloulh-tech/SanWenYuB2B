## 2. 核心理解与建议

### 2.1 分类不要混用三个维度

本轮需求同时出现“鳟鱼”“大西洋鲑”“整鱼”“鱼柳”“挪威”等概念，它们分别属于三个维度：

- 品种：大西洋鲑、银鲑、帝王鲑、虹鳟等。
- 产品形态：整鱼、鱼柳、鱼排、切片、鱼骨/鱼头等副产物。
- 产品产地：挪威、智利、法罗群岛、冰岛、加拿大、美国、中国等。

建议页面统一使用“产品形态”，不使用含义较模糊的“产品形式”。供应商所在地继续保留为“发货地/供应商所在地”，不得与“产品产地”混为一项。

### 2.2 鳟鱼的归类

鳟鱼是鱼种，不建议成为与“鲜鱼产品、养殖供应、深加工品、其他海产”并列的第五个一级分区。建议：

- 商品大厅仍保留四个一级分区。
- 鳟鱼作为“鲜鱼产品”下的品种出现，商品可有整鱼、鱼柳、切片等形态。
- 发布采购时显示完整路径，例如“鲜鱼产品 / 鳟鱼 / 整鱼”。

这样既满足“新增鳟鱼”，也不会破坏领导已经看到的四分区结构。

### 2.3 鱼卵与鱼苗必须拆成独立商品

现有“鱼卵鱼苗”合并项拆为：

- 鱼卵：按“枚”计价，规格重点展示品种、种源国家、发育阶段和包装/运输方式。
- 鱼苗：按“尾”计价，规格重点展示品种、种源国家、单尾克重和活水运输要求。

建议首批演示至少展示 2 个鱼卵 SKU 和 2 个鱼苗 SKU，以便体现美国、挪威等种源差异：

| 商品 | 品种 | 产品产地/种源 | 演示计价 |
| --- | --- | --- | --- |
| 挪威系大西洋鲑发眼卵 | 大西洋鲑 | 挪威 | 元/枚 |
| 美国系虹鳟发眼卵 | 虹鳟 | 美国 | 元/枚 |
| 挪威系大西洋鲑鱼苗 | 大西洋鲑 | 挪威 | 元/尾 |
| 美国系虹鳟鱼苗 | 虹鳟 | 美国 | 元/尾 |

具体价格、起订量、库存、供应商名称均属于平台演示数据，不从外部网页抄成“真实在售报价”。

### 2.4 海马按受监管商品处理

海马属 `Hippocampus spp.` 涉及 CITES 附录 II 国际贸易管理，不宜在页面中表现为无门槛普通鲜活海鲜。建议商品定位为：

- 名称：“人工养殖海马干品（资质审核）”。
- 形态：干品；规格使用长度与包装重量。
- 价格：“资质审核后询价”。
- 详情醒目标注“演示商品；实际交易需核验合法来源及相关许可”。
- 不提供“一键直接采购”，保留“提交询价/发布需求”。

### 2.5 西施舌采用可核验的物种与地域口径

建议名称使用“日照鲜活西施舌”，详情补充“又称沙蛤/海蚌，演示品种口径为西施马珂蛤”。规格字段使用“壳长 + 每公斤只数”，首版演示值可设为“壳长 8-10 厘米，10-15 只/千克”；价格、起订量和供货能力明确为演示数据。

科普资料同时提示其部分海域野生资源承压，因此商品说明应写“人工养殖/合规采捕来源”，不写成无限量野生捕捞商品。

## 3. 建议分类树

发布采购需求的“采购品类”使用二到四个逐级出现的紧凑联动选择控件。初始只显示大品类，选择后依次显示细分品类、产品形式或品种、种源国家；上级变化时清空后续层级。所有层级均按全分类树最长选项统一固定宽度，不再展示密集完整路径长列表。

| 一级品类 | 二级/三级选项 |
| --- | --- |
| 鲜鱼产品 | 三文鱼 / 整鱼、鱼柳、鱼排、切片、鱼骨鱼头等副产物；鳟鱼 / 整鱼、鱼柳、切片 |
| 养殖供应 | 鱼卵 / 大西洋鲑 / 挪威、鱼卵 / 虹鳟 / 美国、鱼苗 / 大西洋鲑 / 挪威、鱼苗 / 虹鳟 / 美国、饲料、鱼药疫苗、养殖设备 |
| 深加工品 | 烟熏产品、鱼饼、预制菜 |
| 其他海产 | 虾类、蟹类、扇贝、生蚝、海马、西施舌 |

说明：2026-08-14 用户进一步确认，鱼卵和鱼苗的采购分类路径需继续细分到品种和种源国家。当前仅接入 `SALMONDIGITA-10` 已建立的“大西洋鲑 / 挪威”与“虹鳟 / 美国”演示数据，不虚构更多组合。

## 5. 数据模型调整

建议在现有商品数据上增补以下字段，不引入后端模型：

```js
{
  species: '大西洋鲑',
  origin: '挪威',
  productForm: '冰鲜整鱼',
  unit: 'kg',
  sourceType: '养殖',
  complianceNote: '',
}
```

- `origin`：产品产地/种源国家。
- `region`：供应商所在地或发货地，保留现有含义。
- `species`：鱼种/物种。
- `productForm`：整鱼、鱼柳、切片等商品形态。
- `unit`：鱼卵为枚、鱼苗为尾、鲜鱼通常为 kg、设备为套。
- `complianceNote`：海马等受监管商品的演示提示。

行情演示数据独立为筛选键值矩阵，不直接把商品大厅参考价冒充成交行情。

## 6. 开发批次与顺序

### Dashi 任务结构

本轮使用“1 个总任务 + 5 个子任务”，不把跨页面改动塞进一个验收单，也不按 13 条反馈机械拆成 13 个零散任务。

| Dashi | 定位 | 覆盖反馈 | 依赖 |
| --- | --- | --- | --- |
| `SALMONDIGITA-9` | 总任务：统一范围、顺序和最终收尾 | 1-13 | 不作为单一页面验收单 |
| `SALMONDIGITA-10` | 商品分类、产地与详情 | 1、2、3、6、10、12 | 共享数据基线，优先实施 |
| `SALMONDIGITA-11` | 发布采购品类与联系方式 | 4、5、10 | 被 `SALMONDIGITA-10` 阻塞 |
| `SALMONDIGITA-12` | 行情筛选与版面 | 7、11 | 被 `SALMONDIGITA-10` 阻塞 |
| `SALMONDIGITA-13` | 大屏供求播报 | 8、9 | 可独立实施 |
| `SALMONDIGITA-14` | 首页热门现货滚动 | 13 | 被 `SALMONDIGITA-10` 阻塞 |

`SALMONDIGITA-10`、`12`、`13` 分别与既有商品、行情和大屏任务建立关联，用于保留返修历史，但不把旧任务重新包装成此次总任务。

### 批次一：共享分类、商品与采购发布（建议 0.75 个工作日）

- 建立共享分类选项和商品字段。
- 拆分鱼卵/鱼苗，新增鳟鱼、海马、西施舌。

### 批次二：市场行情筛选与版面腾挪（建议 0.5 个工作日）

- 建立行情筛选演示数据。
- 联动今日市场和 ECharts 7/30/90 日走势图。

- 补筛选联动和演示数据标识测试。

### 批次三：首页滚动与运营大屏供求播报（建议 0.5 个工作日）

- 首页热门现货改为无缝横向滚动。
- 大屏用实时供求信息替换平台运行状态。
- 检查动画循环、暂停、减少动态效果和定时器清理。

### 批次四：统一验收与文档收尾（建议 0.25 个工作日）

- 执行相关自动测试、全量测试、静态资源检查和生产构建。
- 浏览器检查 1366×768 与 1920×1080；重点检查无整页横向滚动、核心内容首屏可见、下拉框可用、筛选联动、动画不遮挡文字、控制台无错误。
- 同步 Dashi、`docs/CURRENT_STATE.md`、`docs/PAGES_AND_FLOWS.md`、`docs/REQUIREMENTS.md`；若最终确认海马合规展示规则等长期产品口径，再同步 `docs/CHANGELOG.md`。

预计总量：约 2 个工作日。若需要重新生成并逐张验收 5 类以上商品图片，图片准备另计约 0.5 个工作日。
