# 需求与项目变更记录

只记录影响项目方向、页面范围或开发规则的变化，不记录每个小样式调整。

## 2026-08-13

- 明确平台覆盖三文鱼全产业链，并逐步扩展其他海产品。
- 明确交易对象包括商品、产业服务、供应信息和采购/服务需求。
- 新增 B2C 方向，采用统一门户下的“企业交易 / 消费零售”双频道。
- 明确企业频道内的采购方、供应方和服务商身份切换不等同于频道切换。
- 明确核心用户包含大量 40+、50+、60+ 产业经营者，页面需简洁易用。
- 明确 PC 页面核心任务尽量首屏完成，页面几乎无向下滚动，但长内容允许合理纵向滚动。
- 明确当前只做快速前端静态演示和简单点击跳转，不提前建设复杂后端能力。
- 明确所有新增和修改只保存本地仓库，未经授权不得上传 GitHub 或其他远程仓库。
- 本地归档 10 张 UI 原稿和 36 页项目方案 PPT。
- 建立独立 Dashi 项目“三文鱼数字化交易平台”，后续按阶段和业务链路跟踪。
- 修复页眉品牌图本地资源缺失和 1366px 宽度下文字裁切问题。
- 清理商品详情、采购和帮助页中已发现的 React 列表标识警告。
- 增加静态资源缺失检查和基础回归测试，保持轻量但可快速发现明显演示故障。
- 建立 `docs/CURRENT_STATE.md` 项目恢复入口，并统一 Dashi 单任务结论格式和新会话最小恢复顺序。
- 新增页面确认规则：任何页面新增或改动必须先提交文字草图，取得用户明确确认后才能实施。
- 冻结 B2B/B2C 身份方案：由两个固定频道入口调整为统一账号下的单个“当前身份”切换按钮，并明确游客、仅个人、仅企业和双身份规则。
- 新增并验收消费零售首页：包含三代同堂家庭海鲜横幅、四个大分类入口、七件热门推荐及企业/个人频道跳转；商品图为本地生成素材。
- 开发流程调整为轻量迭代：每页只保留一次必要测试/构建和用户验收，未经用户要求不主动使用独立审查代理。
- 进一步消除轻量流程歧义：小型静态演示页面在文字草图确认后直接开发，不另写正式设计规格或实施计划、不重复请求确认；仅在跨业务链路、重大方向选择或用户明确要求时使用正式规格和计划。
- 精简项目指令上下文：`AGENTS.md` 只保留始终生效的硬规则与文档路由；开发、验证、Dashi 和汇报流程统一迁入 `docs/DEVELOPMENT_WORKFLOW.md`；`docs/CURRENT_STATE.md` 只保留恢复所需的当前事实。
- 固化任务收尾门禁：每次请求验收或关闭任务前必须同步 Dashi 与当前状态；页面、路由和业务链路变化同步页面链路文档，需求范围变化同步需求文档，产品方向和长期规则变化同步变更记录；存在状态、文档或提交不一致时禁止关闭任务。
