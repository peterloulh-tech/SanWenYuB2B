# 需求与项目变更记录

只记录影响项目方向、页面范围或开发规则的变化，不记录每个小样式调整。

## 2026-08-24

- 平台品牌统一为用户确认的透明“日照三文鱼交易平台”Logo 加 HTML 平台名；该 Logo 代表整个平台，不进入商品卡、商品详情或认证标识。企业与个人消费页头均新增“日照产业”，首页口号和唯一官方购买渠道标识按本轮确认口径更新。
- 当前可见商品范围收紧：企业端暂时隐藏“其他海产”分区及 6 项商品，个人消费端调整为 4 个纯三文鱼分类和 7 件商品；旧分区、其他海产和指定旧零售商品代码均注释保留，未删除。
- 平台承担主体统一为山东万泽丰海洋开发集团有限公司、山东旭丰渔业有限公司和日照深海三文鱼产业协会，并新增真实主体详情链路；缺失 Logo、职责、主体资料和视频必须显示“资料待补充”，不得生成或挪用标识。
- 新增简单日照银行批次溯源、日照产业、三文鱼百科、三文鱼厨房及专利成果合作意向等本地静态演示链路。溯源不扩展加工链、冷链时间线或批次关系；专利不扩展真实估值、竞价、合同、支付或权属变更。
- 外部事实继续要求来源、日期和原文链接；未确认事实显示“资料待补充”，本地模拟商品、批次、菜品、专利和提交结果明确标注演示数据。

## 2026-08-17

- 经用户明确授权，GitHub 仓库 `peterloulh-tech/SanWenYuB2B` 成为项目唯一默认推送目标：`main` 分支继续保存 GitHub Pages 生产构建产物并提供固定公网演示，`source` 分支保存完整项目源码和本地 Git 历史。原始源码仓库 `singleMen/salmon-digital-platform` 仅保留为只读 `upstream`，后续不得向其推送。远端更新仍需用户明确授权。

## 2026-08-15

- 扩展“硅小智”卡通 AI 入口方向：企业首页、商品大厅、供应商大厅、产业服务、采购大厅、订单中心和个人消费首页统一提供浏览器中文语音转文字与本页综合搜索；关键词默认跨分类，用户可再按分类收窄。入口改为上图下签并支持拖拽后自动吸附浏览器左右边缘，兼容标准及 `webkit` 语音识别接口，不保存录音。后续渔业问答和站内统计只允许访问匿名普通用户公开可见的白名单数据，禁止直接访问完整数据库和内部数据。
- B2B/B2C 公共页头入口由单个“当前身份”下拉按钮调整为“企业交易 / 个人消费”常驻双频道分段切换；选中频道采用实色块，频道内主导航继续采用文字加底部线。统一账号、多身份以及个人开通/企业入驻提示策略不变。
- 企业首页移除重复的“今日市场”面板，市场行情继续由顶部导航承接；快捷入口下方改为与第二排四张快捷卡片共用四列边界，热门现货跨前两列，最新采购需求和优质供应商分别对齐第三、第四列。

## 2026-08-14

- 商品口径统一拆分为“品种、产品形态、产品产地/种源国家”三个维度，供应商所在地继续作为独立字段，不再用“产地”混指发货地。
- 企业商品大厅保持鲜鱼产品、养殖供应、深加工品、其他海产四个一级分区；鳟鱼作为品种归入鲜鱼产品，鱼卵与鱼苗拆为独立品类并分别按枚、尾计价。
- 其他海产增加西施舌及受监管的人工养殖海马干品；海马仅提供资质审核后询价，并长期要求展示合法来源、经营资质和相关许可提示。
- 资讯中心分类由“综合、国家政策、时事新闻”扩展为“综合、国家政策、时事新闻、行业资讯”。
- 行业资讯首批收录微信公众号“壹渔业”最近 20 篇已核对文章，保留发布日期、摘要、内容分类、标签和公众号来源说明；无法取得稳定微信原文链接时不伪造外链。
- 国家政策与时事新闻首批各补充 5 条国内官方网站内容，覆盖渔业法律、中央文件、海洋经济、水产种业、渔船安全及近期养殖预警和生产监测；详情保留来源、日期、分类标签和官网原文链接。

## 2026-08-13

- 明确平台覆盖三文鱼全产业链，并逐步扩展其他海产品。
- 明确交易对象包括商品、产业服务、供应信息和采购/服务需求。
- 新增 B2C 方向，采用统一门户下的“企业交易 / 消费零售”双频道。
- 明确企业频道内的采购方、供应方和服务商身份切换不等同于频道切换。
- 明确核心用户包含大量 40+、50+、60+ 产业经营者，页面需简洁易用。
- 明确 PC 页面核心任务尽量首屏完成，页面几乎无向下滚动，但长内容允许合理纵向滚动。
- 明确当前只做快速前端静态演示和简单点击跳转，不提前建设复杂后端能力。
- 明确所有新增和修改只保存本地仓库，未经授权不得上传 GitHub 或其他远程仓库。
- 本地归档 10 张 UI 原稿和 36 页项目方案 PPT。
- 建立独立 Dashi 项目“三文鱼数字化交易平台”，后续按阶段和业务链路跟踪。
- 修复页眉品牌图本地资源缺失和 1366px 宽度下文字裁切问题。
- 清理商品详情、采购和帮助页中已发现的 React 列表标识警告。
- 增加静态资源缺失检查和基础回归测试，保持轻量但可快速发现明显演示故障。
- 建立 `docs/CURRENT_STATE.md` 项目恢复入口，并统一 Dashi 单任务结论格式和新会话最小恢复顺序。
- 新增页面确认规则：任何页面新增或改动必须先提交文字草图，取得用户明确确认后才能实施。
- 冻结 B2B/B2C 身份方案：由两个固定频道入口调整为统一账号下的单个“当前身份”切换按钮，并明确游客、仅个人、仅企业和双身份规则。
- 新增并验收消费零售首页：包含三代同堂家庭海鲜横幅、四个大分类入口、七件热门推荐及企业/个人频道跳转；商品图为本地生成素材。
- 开发流程调整为轻量迭代：每页只保留一次必要测试/构建和用户验收，未经用户要求不主动使用独立审查代理。
- 进一步消除轻量流程歧义：小型静态演示页面在文字草图确认后直接开发，不另写正式设计规格或实施计划、不重复请求确认；仅在跨业务链路、重大方向选择或用户明确要求时使用正式规格和计划。
- 精简项目指令上下文：`AGENTS.md` 只保留始终生效的硬规则与文档路由；开发、验证、Dashi 和汇报流程统一迁入 `docs/DEVELOPMENT_WORKFLOW.md`；`docs/CURRENT_STATE.md` 只保留恢复所需的当前事实。
- 固化任务收尾门禁：每次请求验收或关闭任务前必须同步 Dashi 与当前状态；页面、路由和业务链路变化同步页面链路文档，需求范围变化同步需求文档，产品方向和长期规则变化同步变更记录；存在状态、文档或提交不一致时禁止关闭任务。
- 资讯中心的内容分类由五类收缩为“综合、国家政策、时事新闻”三类，分类操作放入紧凑标题横幅。
