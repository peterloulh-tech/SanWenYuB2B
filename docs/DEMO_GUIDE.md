# 快速前端演示开发指南

## 开发目标

用最短时间交付视觉完整、业务清楚、主要链路可点击的 PC 静态页面。页面数量不是主要验收标准，完整可讲解的业务链路更重要。

## 页面开发方式

推荐按业务链路开发，而不是按孤立页面堆数量：

1. 确定本轮演示主题。
2. 明确入口、列表、详情、确认和结果页面。
3. 为每个新增或改动页面提交文字草图，等待用户明确确认。
4. 确认后准备一组一致的 Mock 数据。
5. 串通主要按钮和返回路径。
6. 检查主流屏幕首屏效果。
7. 构建验证后再扩展下一条链路。

### 文字草图最低内容

- 页面名称和路由。
- 从上到下的主要区域和各区域核心内容。
- 主按钮、次按钮及点击后去向。
- 与其他页面的进入、返回关系。
- 本轮明确不做或不改的内容。

文字草图确认的是信息结构和演示流程，不要求提前决定像素、颜色细节或技术实现。

## PC 适配与低滚动规则

重点检查：1920×1080、1600×900、1440×900、1366×768，兼顾 1280×720。

- 首页、列表页、工作台和确认页的核心任务应尽量在首屏内完成。
- 列表数量过多时使用分页、标签切换或内容区域局部滚动。
- 商品详情、新闻、政策等长内容允许正常向下滚动，但标题、核心数据和主操作必须在首屏。
- 页面不得整体缩放来适配小屏，不使用 `transform: scale()` 压缩整个页面。
- 禁止整页横向滚动；复杂表格、地图可在自身区域内滚动。
- 屏幕高度不足时优先减少装饰、推荐位和次要说明，不缩小关键文字与按钮。

“几乎无向下滚动”指核心任务首屏完成，不等于所有页面绝对不能滚动。

## 中老年用户友好

- 正文通常不低于 16px，关键数字和主按钮更大。
- 主按钮尽量使用完整动词，如“发布采购需求”“查看供应商报价”。
- 少用只有图标没有文字的关键操作。
- 单页突出一个主要任务，避免同时出现多个同等级主按钮。
- 表单字段尽量少，提供默认值、示例和清晰单位。
- 状态同时使用文字和颜色表达。
- 保留清晰导航、面包屑、返回和下一步入口。

## 视觉与代码

- UI 原稿是当前视觉基准，新页面应延续白底、深蓝文字、主题蓝按钮和轻边框卡片风格。
- 页面内容区域保持统一左右基线，桌面端可沿用最大 1516px 容器。
- 优先复用现有布局、按钮、卡片、标题和状态样式。
- 不要求先做全仓库重构。修改相关页面时再局部整理。
- 静态图片应保存到本地项目资源，不依赖临时外链。

## Mock 数据与联网资料

- 纯演示数字可使用 Mock 数据，但不要伪装成真实实时数据。
- 政策必须优先引用原始发布机关页面，记录发布单位、日期、文号和链接。
- 新闻记录标题、来源、发布时间、摘要和原文链接。
- 行情记录地区、品类、规格、单位和采集时间。
- 公众号和自媒体只作为线索，正式展示前尽量找到原始或权威来源。
- 不整篇复制新闻，不直接盗用来源不明图片。
- 联网资料与本地演示 Mock 数据分开维护。

## 每轮最低验证

- 关键路由和按钮跳转可用。
- 本轮涉及页面无明显溢出、遮挡或整页横向滚动。
- 本地静态资源存在。
- `pnpm build` 成功。
